# 验证记录

验证环境：2026-09-14，Windows，Node.js 24.16.0、npm 11.13.0。

本机结果：118 项自动化测试全部通过，严格类型检查、构建、编译后服务的 HTTP 烟雾测试和管理页脚本语法检查通过。使用独立临时浏览器环境完成 Headless Edge 的桌面与手机页面交互检查。

## 可复现的检查

```sh
npm ci
npm run check
node scripts/smoke.mjs
node --check apps/api/public/app.js
```

自动化测试包含 WeChat-AI 的协议测试，以及新系统的下列行为：

| 范围         | 验证内容                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------- |
| 接收与对话   | 原文和任务原子保存、重投去重、真正的新消息、连发时旧草稿失效                             |
| 投递与恢复   | 已确认气泡不重发、部分发送恢复、送达不明暂停、备份恢复后不自动重发                       |
| 记忆与日记   | 联系人隔离、来源与说话人、明确纠正、后台旧结果、增量日记、后续召回                       |
| 长历史       | 超过近期窗口仍能检索，删除原文清理所有依赖，很多短消息也触发笔记                         |
| 上下文与工具 | 近期原话优先、token 预算缩减、超限保留原文、有限工具循环、实时来源                       |
| 模型适配     | 三种接口格式、工具续接、图片预算、自定义温度与输出上限、日记上限、密钥脱敏               |
| 管理与接入   | 登录、Cookie、来源校验、独立试聊、参数持久保存与原子校验、实际用量、联系人允许、模拟扫码 |
| 主动联系     | 默认关闭、安静时段、沉默时间、每日限制、模型可以跳过                                     |
| 备份         | 数据库一致快照、媒体清单、校验和与空目录恢复                                             |

scripts/smoke.mjs 启动编译后的实际服务器子进程和本地 HTTP 模型替身，经由 HTTP 检查健康状态、静态管理页与图片、登录、参数即时应用、持久对话、去重、记忆、日记、调用用量和备份。请求捕获确认网页设置的温度和输出上限进入实际聊天与日记请求。

浏览器检查使用 1440 × 1000 桌面和 390 × 844 手机视口，连接同一份临时服务：登录与退出、六个栏目和快捷入口、键盘导航、预算与超时校验、保存并刷新、轮询期间保留未保存编辑、普通文字人物设定、队列试聊、增量日记、来源弹窗、表情图片和最近调用显示全部通过。页面没有脚本异常或横向页面溢出，并检查了登录、首页、调试页和日记的截图。浏览器测试工具安装在临时目录，不增加应用依赖。

这些测试证明程序在所覆盖输入下的行为，不证明真实模型的人物表达、事实判断或自然程度。

## 尚未在本机验证

- 本机没有 Docker，尚未完成实际镜像构建和 Compose 运行。当前 GitHub 登录凭据不具备修改 Actions 工作流的 workflow 权限，因此 Linux 检查与 Docker 构建配置以 [手动启用模板](examples/check.yml) 提供，尚未运行 CI。

- 未使用真实微信账号扫码收发；协议测试和扫码流程使用本地替身，实际账号资格、媒体显示与会话限制需上线前检查。

## 配置真实服务后的试用

| 场景                     | 应观察什么                                               |
| ------------------------ | -------------------------------------------------------- |
| 初次聊天                 | 自然认识对方，没有凭空的共同过去                         |
| “我吐槽时先听我说完”     | 后续倾诉先倾听；明确要求建议时能切换                     |
| “不是周五，是周六”       | 新说法优先，查看依据能够找到纠正记录                     |
| 隔天提起昨天的经历       | 找到原文或日记，保留真实细节，主观感受不变成对方事实     |
| 换一种说法提起旧事       | 检索是否能找到；若无词面重合，观察模型能否更换关键词核实 |
| 询问当前天气或新闻       | 实际调用联网工具，给出可打开的来源；失败时坦诚说明       |
| 发送图片和表情           | 视觉模型读取图片，后续描述有依据，多气泡顺序正确         |
| 快速连发、更正、暂时断网 | 旧草稿作废，确认过的气泡不会重复发送                     |
| 删除一段经历             | 日记、记忆、笔记与检索中不再带回已删除来源               |
| 主动联系                 | 只在允许时段、有实际话题时发生；没有话题可以整天不发     |

试用时记录实际回复、工具调用次数、耗时和 token 使用。人物表现主要调整提示词；只有出现可复现的来源、检索或流程问题时才增加程序机制。
